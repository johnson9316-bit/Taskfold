# 路线图与验收

> 跨主题请从 [[README]] 进入；发现矛盾时以 [[1-规划评审]] 为准。

**当前路线。** Taskfold 的唯一产品形态是 OpenClaw 插件；M1 以官方 Workboard 固定快照为基线，后续路线保留若干调整节点，并在成熟节点逐步叠加 GSD 工作控制台能力。

| 里程碑 | 目标 | 关键交付 |
|--------|------|---------|
| **M1** | **Taskfold OpenClaw 看板插件** | 完整复制固定快照的 OpenClaw Workboard 功能层，按其代码和规范打包为可本机安装、可从 Git 仓库安装的 `taskfold` 插件。详细规格见 [[8.1-Taskfold看板插件]]。 |
| **M2** | **看板通用功能改造** | 在复制的 Workboard 基础上引入多项目、项目设置与项目资料；现有 Board 提升为项目，卡片继续沿用上游 Board/Card 模型。需求见 [[8.2-需求]]，实施计划见 [[8.2-看板通用功能plan]]。 |
| **M3** | **通用面板改造** | Card 真实交付记录、来源资料与安全 Markdown Documents 阅读器；不做 GSD 扫描或映射。详细规格见 [[8.3-通用面板改造]]。 |
| **M4** | **OpenClaw 开发执行集成**（核心） | 经官方 ACP Runtime + `@openclaw/acpx` 在隔离 worktree 执行单个 run，并具备观察、人工接管、恢复和审计能力。详细规格见 [[8.7-待开发一波]]。<br>⚠️ **原含的「GSD 内化」已拆出并推迟**（[[1-规划评审]] 决策 6）：`.planning/` 只读投影、可重建索引、phase/plan/wave 可视化均不在本版本范围。 |
| **M6** | 基于上一步进行调整 |  |
| **M7** | **流程、规划与 Skills 增强** | 在稳定的数据模型和执行账本之上补齐流程管理、路线图、当前重点、检索、规划产物和受控的多 worktree 并行。详细规格见 [[8.5-流程规划与Skills增强]]。 |
| **M8** | 基于上一步进行调整 |  |
| **M9**\* | **AI、自动化与度量** | 为外部开发助手提供 MCP；以人工批准为前提提供 AI 建议和自动化；把工作项、GSD 投影和 run 账本转化为度量、复盘和周期报告。详细规格见 [[8.4-AI自动化与度量]]。 |

## 已细化的里程碑

| 总览节点 | 详细规格 | 退出门 |
|---|---|---|
| **M1** | [[8.1-Taskfold看板插件]] | Workboard 功能层完整导入并可与原生 Workboard 并存；退出前必须完成本机链接安装、运行时检查、功能冒烟和 Git 分发复验。 |
| **M2** | [[8.2-需求]]（需求）<br>[[8.2-看板通用功能plan]]（实施） | 多项目、项目设置和项目资料可日常使用；M1 Board/Card 数据无损升级；原生 Workboard 可并存，Git 安装复验通过。 |
| **M3** | [[8.3-通用面板改造]] | Card 的执行状态、开发/验证/发布事实和来源资料彼此独立；Documents 可安全按需阅读明确绑定的 Markdown 原文，且不扫描或索引 GSD。 |
| **M4** | [[8.7-待开发一波]] | 单 repo、单 worktree 的官方 ACP harness run 可观察、可接管、可终止并可复盘。（原退出门「一个真实 GSD 项目的投影可对账」随 GSD 内化一并推迟。） |
| **M7** | [[8.5-流程规划与Skills增强]] | 流程、规划、检索和可选 Skills 都可追溯；受控并行在显式人工确认下可用。 |
| **M9** | [[8.4-AI自动化与度量]] | MCP、AI、自动化和度量均在权限、确认、审计和可追溯数据边界内运行。 |

## 占位节点

M6 和 M8 是当前路线中的预留调整节点。它们在目标、范围和验收尚未明确前不创建详细规格，也不提前承诺实现。
