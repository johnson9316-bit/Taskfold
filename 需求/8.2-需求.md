# M2 需求：看板通用功能改造

> 跨主题请从 [[README]] 进入；发现矛盾时以 [[1-规划评审]] 为准。本文件定义 **M2 做什么、为什么做、如何验收**。具体代码改动、顺序和验证方法见 [[8.2-看板通用功能plan]]。

## 命名与发布前提

产品名称统一为 **Taskfold**，它是一个 OpenClaw 原生插件，而不是 `gsd-core` 的界面或附属产品。

- 品牌、仓库和本机源码目录使用 `Taskfold`：Git 仓库为 `johnson9316-bit/Taskfold`，开发目录为 `/home/john/src/personal/Taskfold`。
- 所有机器可调用的公开命名空间统一使用小写 `taskfold`：插件 ID、npm 包名、CLI、slash command、Gateway RPC、工具名、Tab 路径、SQLite 文件和数据表均不得再使用旧产品命名。
- `workboard` 仅可作为固定上游来源、内部导入目录和适配层名称出现；不得成为 Taskfold 的公开接口。
- 这次更名发生在 Taskfold 首次公开分发前，因此不保留旧插件 ID、别名、RPC 或工具名。旧本机插件和其 SQLite 数据必须保持原样，不做隐式复制、移动或删除；日后如需导入，必须以单独、可预览且幂等的数据迁移立项。

## 目标

M1 将 OpenClaw Workboard 复制为 Taskfold 插件，但其看板仍是简略的工作项容器。M2 要把它变成可用于日常研发管理的通用项目看板：

1. 同一 Taskfold 中可管理多个项目，而不是只面对一块无上下文的看板。
2. 每个项目有独立的设置、看板、配置中心和资料库；主看板按里程碑列组织需求卡片，不再按执行状态分列。
3. 用户可以记录项目背景、当前目标、仓库、环境、代码库知识和规划资料，而不必把这些信息塞进某张卡片。

M2 不接入 GSD，也不新增开发执行能力。它先把“项目”这个通用基础补齐，为 M4 的 GSD 投影和执行集成提供稳定的项目归属。

M2 的关键改造是将“看板位置”与“执行状态”拆开：里程碑列负责组织项目需求，Card `status` 继续负责 Workboard 既有的领取、派发、运行、阻塞、依赖和完成生命周期。把卡片拖到另一列不能改变其 `status`、领取、执行记录或生命周期时间；更新状态也不能改变其所属里程碑或列内位置。

## 产品定义

### 项目与现有 Board

M2 中，用户看到和操作的是 **项目（Project）**；一个项目在当前版本对应一块现有的 Taskfold Board。

- 项目 ID 复用 Board ID，是项目的稳定且不可修改的键；它必须满足 M1 已有的 Board ID 格式、在项目列表中唯一，冲突时明确拒绝创建。
- 一个项目恰好有一块主看板；看板的每一列是一个里程碑，列中的需求卡片是该里程碑下的具体小需求。
- Board/Card 仍是 Taskfold 从 Workboard 继承的内部模型。M2 不把卡片改造成另一套 `work_item` 模型，也不迁移或重建现有卡片数据。
- 未来的“一个项目多个 Board”不属于 M2。

### 里程碑与小需求

M2 的工作层级固定为：

```text
Project / Board
└── Milestone / 看板列
    └── Requirement Card / 需求卡片（具体小需求）
```

- 里程碑是项目内有序的看板列，不是独立的时间轴、Release 或另一份 Markdown 路线图。
- 里程碑至少包含名称、目标或说明、颜色、排序和完成/归档状态。
- 小需求以现有 Card 承载，用户在看板上看到的是一张张需求卡片；卡片必须归属一个里程碑，在列之间拖拽卡片就是变更其里程碑归属。
- Card 原有的 `status`、优先级、评论、依赖、附件和运行信息继续保留。M2 中 `status` 是独立的执行状态，可在卡片详情、筛选和执行操作中查看或更新，不再是主看板的列。
- 移动或排序需求卡片只改变其里程碑归属和列内位置；它不能触发 `status` 流转、领取/释放、派发、阻塞/解除、完成/恢复或任何执行记录变化。
- 执行操作仍按 M1 的规则更新 `status`：例如领取可进入运行中、阻塞/解除和完成会更新其执行生命周期；这些操作不移动卡片的里程碑列。
- 创建项目时，用户必须给出首个里程碑的名称；表单可预填“第一里程碑”，但不把固定状态列伪装成里程碑。项目、首个里程碑和基础资料目录必须原子创建。
- M1 已有但未归属里程碑的卡片显示在“未归属”迁移列，用户可将其拖入真实里程碑。
- 已完成或归档的里程碑默认不接收新卡片；恢复后可以再次接收卡片。
- 里程碑只有在其中所有未归档 Card 都处于 M1 的终态后才能标记完成；不允许“完成里程碑”顺带修改 Card `status`。不满足条件时必须列出未完成 Card 并拒绝操作。

### 项目设置

用户可在项目设置中维护：

| 类别 | 内容 |
|---|---|
| 身份 | 项目名称、项目 ID、图标或颜色。 |
| 项目概览 | 项目简介、核心价值、当前版本、当前目标和权威需求来源。 |
| 工作上下文 | 默认本地工作区、仓库地址、规划目录路径、主页或文档首页。 |
| 管理 | 项目排序、归档和恢复。 |

默认本地工作区是项目的工作上下文：从项目内新建卡片时，卡片应继承该设置。M2 只处理归属和继承，不因设置工作区而自动派发、创建 worktree 或执行任务。

> ⚠️ **收紧为必填（2026-09-18，因 [[16-文件存储改造]] §5.3 定案更新）**：本节未明确该字段是否必填，本文原意留待项目设置逐步补充；[[16-文件存储改造]] 走文件存储改造（B2：卡片数据入 `<repo>/.taskfold/`）后，默认本地工作区（`kind` 为 `dir` 或 `worktree`）**收紧为创建项目时必填**，不再支持无本地仓库的项目——因为它同时要回答"数据存哪"，不再只是"agent 在哪跑"。详见 [[16-文件存储改造]] 5.3。

### 项目配置与资料库

项目资料不是散乱的链接列表，而是项目的长期上下文。M2 提供一个固定的资料目录，并允许在各目录中补充自定义资料：

| 资料区 | 基础条目 | 用途 |
|---|---|
| 项目 | 项目概览、项目配置、需求、路线图、当前状态、复盘 | 保存项目章程、当前焦点、范围、决策和阶段性结论。 |
| 代码库 | 架构、技术栈、目录结构、编码约定、测试、外部集成、风险/技术债 | 让开发前可快速理解代码库的边界、规则和脆弱区域。 |
| 环境与发布 | 本地开发环境、测试/部署环境 | 保存访问入口、非敏感运行说明、构建、发布和验证流程。 |
| 知识沉淀 | Notes、Research、Todos、Seeds、Onboarding | 保存持续积累的设计说明、调研、待办、原始材料和接手说明。 |

每个资料项都有稳定 key、标题、资料区、可选摘要、排序和更新时间，支持以下载体：

| 载体 | 用户可保存的内容 |
|---|---|
| Markdown 文档 | 在 taskfold 中维护的项目说明、规划、约定、环境说明和笔记。 |
| JSON 配置 | 可阅读、可校验格式的项目配置文档；M2 只保存和展示，不执行其中的 GSD 或自动化设置。 |
| 链接 | 外部文档、仓库、Issue、网页或内部系统入口。 |
| 本地路径 | 仓库内或本机的文档、目录、文件或现有 `.planning` 条目路径。 |
| 密钥引用 | 凭据所在的密码管理器条目名、环境变量名或受控文件路径；不保存密钥值。 |

里程碑本身以看板列为唯一真相，不再与资料库中的 Markdown “里程碑列表”重复维护。需要保留历史交付说明时，用户可在项目资料区使用复盘或自定义资料条目。

新建项目时，系统应创建上述固定资料目录中的空白基础条目和用户指定的第一个里程碑；用户可填充、隐藏不需要的资料条目或在资料区新增自定义条目。已有 M1 Board 升级后也必须获得同一套空白目录，但不覆盖任何已有 Board/Card 数据。

M2 借鉴真实 `.planning` 的信息组织方式，但不读取、导入、同步或写回 `.planning`。M4 才定义 Taskfold 与 GSD 文件之间的正式映射和真相边界。

资料仅被保存和展示。M2 不上传或复制文件，不读取本地路径内容，不同步外部地址，也不做 AI 摘要或知识库检索。本地路径只校验格式和长度，不要求路径存在、不解析其内容，也不据此授予工作区访问权限。

### 敏感信息边界

开发、测试和部署资料常含账号、Token、密码、数据库连接串或生产地址。M2 的规则是：

- 不提供密码、Token、Cookie、私钥或完整连接串的专用输入字段，也不自动导入任何本地环境资料。
- 需要记录凭据时，只能保存密钥引用，不能保存密钥值；例如环境变量名、密码管理器条目名或受控文件路径。
- 环境资料中的地址、命令和流程可保存，但 UI 必须提示用户不要粘贴秘密值。
- 后续 M4 即使读取 `.planning`，也必须先定义脱敏和权限策略，不能把既有环境资料原样复制入 Taskfold 数据库。

## 用户可完成的工作

### 1. 浏览与切换项目

- 用户能看到活跃项目列表，包括名称、图标或颜色、卡片数量和最近更新时间。
- 用户能进入“全部项目”总览，也能切换到单个项目。
- 单项目看板只显示其卡片；总览中的卡片按项目分组并清楚识别所属项目，可跳转到对应项目。
- 总览不把不同项目的里程碑列合并成一条假路线图，也不跨项目重排卡片。
- 用户能按项目名称或 ID 查找项目，并调整项目展示顺序。

### 2. 创建、编辑与归档项目

- 创建项目时，用户填写项目 ID、名称、首个里程碑名称和可选设置；系统同时创建项目资料库的基础目录，随后进入该项目看板。
- 项目 ID 创建后不可修改，其他设置可编辑且重启后保留。
- 归档项目会将其从默认项目列表隐藏，保留项目、卡片、评论、关联、附件、运行信息和资料。
- 已归档项目可在归档列表中查看和恢复；归档期间不能创建新卡片、把卡片移入该项目或启动新的派发。
- 归档不取消已经开始的 run，也不丢弃其事件；若项目中存在运行中的 Card，归档必须要求用户明确确认这一事实。
- M2 不提供项目永久删除入口。

### 3. 在项目中管理卡片

- 用户可在项目中创建、编辑、排序、完成、归档和恢复里程碑；完成里程碑必须遵守未完成 Card 的检查。
- 项目看板按里程碑分列；用户可拖拽小需求卡片在里程碑列之间移动并调整列内顺序。
- 在项目看板创建的卡片自动归属当前项目和当前里程碑。
- 卡片详情显示所属项目，并可跳转回项目首页。
- 看板中的拖拽和排序只调整需求的里程碑列与列内顺序；卡片状态通过单独的状态控件和既有执行操作维护。
- 用户可显式把卡片移至另一个活跃项目；操作前必须确认，并选择目标里程碑。
- 移动只改变项目归属，不丢失卡片标题、正文、状态、评论、依赖、附件、证明、运行信息或历史内容；既有卡片关联保持有效，即使因此形成跨项目关联。

### 4. 管理项目配置与资料库

- 项目首页展示项目概览、当前目标、主看板摘要和资料入口。
- 用户可在“项目、代码库、环境与发布、知识沉淀”四个资料区阅读、编辑、排序、隐藏和新增资料。
- 固定资料条目与自定义资料均有明确的类型和最近更新时间；链接、本地路径、Markdown、JSON 和密钥引用不可混淆。
- Markdown 按 Taskfold 已有的安全渲染约束展示；JSON 格式错误必须明确提示；不将不可信内容作为可执行内容。
- 密钥引用只能展示名称或路径，不能回显或导出凭据值。

## 兼容与迁移

- M1 中已有的 Board 直接成为 M2 的项目，不要求用户导出、导入或手工迁移。
- 升级不会改写已有 Card 的 `status`、领取、执行、依赖、评论、附件、历史事件或时间字段；只新增可空的里程碑归属。历史卡片保持未归属并显示在“未归属”迁移列。
- 没有显式 Board 记录、但已有卡片使用的 Board ID，也必须在项目列表中可见并可补充设置。
- 默认 Board 作为默认项目继续可用。
- M2 只在 Taskfold 自己的 SQLite 数据中增加项目配置和资料库；不读取、写入或修改原生 `workboard` 的数据。
- 原生 `workboard` 与 `taskfold` 必须继续同时启用，公开命名空间不得冲突。

## 非目标

- GSD `.planning/` 的读取、投影、同步或写回。
- ACP harness、worktree、run 账本、自动派发、人工接管、巡检或执行调度。
- AI、MCP、自动化、度量、报告、全文检索、GSD 路线图投影、Release、Sprint、WIP 或自定义工作流。
- 多人协作、用户/角色/权限系统、云同步、独立服务或独立 Web 应用。
- 一个项目多个 Board、文件上传或项目级附件仓库、资料的外部同步/双向编辑。
- 自定义 Card 状态机、自由配置状态列或将里程碑扩展为时间轴/Release 计划。
- 删除、替换或放宽 M1 既有的 Card `status` 执行状态机；M2 只改变主看板的组织方式。

## 验收标准

1. **项目与里程碑闭环**：创建至少三个项目；创建时输入首个里程碑名称，每个项目至少有两个里程碑列，并能创建、排序、完成、归档和恢复里程碑。存在未完成 Card 时完成操作必须被拒绝且列出原因。
2. **看板闭环**：单项目看板按里程碑分列；在列中创建小需求卡片、拖拽卡片至另一列、调整列内顺序后，归属和显示均正确。拖拽或排序前后的 Card `status`、领取、执行记录和生命周期时间完全不变；Card 状态仍可通过独立控件和既有执行操作查看、更新，但不作为主看板列。
3. **设置闭环**：项目名称、简介、核心价值、当前版本/目标、权威来源、图标或颜色、默认工作区、仓库/规划目录/主页信息可编辑、持久化，并在重启 OpenClaw 后正确显示。
4. **资料库闭环**：新项目和升级后的 M1 项目均具备项目、代码库、环境与发布、知识沉淀四个资料区及其基础条目；资料可新增、编辑、排序和隐藏。
5. **载体与安全闭环**：Markdown、JSON、链接、本地路径和密钥引用均可正确保存和显示；错误 JSON、URL 或路径获得明确反馈。路径不触发文件读取或工作区授权，界面不保存、不回显凭据值。
6. **卡片归属闭环**：项目内建卡自动归属里程碑；跨项目移动需确认和选择目标里程碑，移动后卡片的既有内容、依赖和关联仍可读取。
7. **归档闭环**：归档项目默认隐藏且不能接收新卡片或新派发；存在运行中 Card 时必须二次确认且不取消 run。完成或归档里程碑不能接收新卡片；恢复后卡片、配置、资料和里程碑完整出现。
8. **M1 兼容**：用已有 Board 与卡片的数据启动 M2 后，全部项目可见，基础资料目录已补齐，原有卡片进入“未归属”迁移列；卡片 ID、Board ID、状态、评论、关联、附件和运行信息均不变。
9. **命名与宿主**：产品显示为 Taskfold，公开插件 ID、CLI、slash command、RPC、工具、Tab 路径和 SQLite 命名空间均为 `taskfold`；原生 `workboard` 可并存且不存在旧产品命名的公开接口。
10. **分发**：在干净 Git clone 安装后，项目创建和既有数据升级均通过冒烟验证。

## M2 退出门

上述十类验收全部完成，M2 才可以标记完成。之后的 GSD 与执行能力必须以 M2 的项目、里程碑、卡片归属、配置与资料库为基础，但不能反向改变本文件的通用项目看板边界。
