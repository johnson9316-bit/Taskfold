# GSD 内化与开发执行集成（路线图 M4 规格）

> 跨主题请从 [[README]] 进入；发现矛盾时以 [[1-规划评审]] 为准。本文件定义 [[8-路线图与验收]] 总览中的 **M4**；它建立在 M2 的项目看板和 [[8.3-通用面板改造]] 的交付事实、资料阅读能力之上。
>
> **执行后端以 [[8.7-待开发一波]] 为准：** M4 使用 `Taskfold ACP Runner` 直接调用
> OpenClaw 公共 ACP Runtime 与官方 `@openclaw/acpx`，不通过 `coding-agent`、LLM Bridge
> 或第三方执行插件。

## 目标

让 taskfold 看得懂一个项目的 GSD 规划产物，并把经过人工许可的开发工作变成安全、可观察、可恢复的异步 run。M4 的核心是“文件规划真相 + SQLite 运行账本”的协作，而不是把 GSD 文件迁进数据库。

## 进入条件

1. 已完成 M1，taskfold 插件已在 OpenClaw 中可安装、可加载、可用，且满足 [[8.1-Taskfold看板插件]] 的退出门。
2. 已通读并 vendor `gsd-core`，确认它究竟是可调用库、CLI 工具还是提示词/会话驱动包；结论必须记录在实现文档和测试记录中。
3. 已实测 taskfold 能通过 OpenClaw 公共 ACP Runtime 调用官方 `@openclaw/acpx`，完成 `ensureSession`、`startTurn`、状态/事件观察、`cancel` / `close`、隔离 worktree 和按 harness 分列的终端接管验证。
4. 目标项目处于允许执行的状态：工作区白名单命中、Git 基线明确、敏感文件排除规则有效、临时 worktree 可创建和清理。

## 范围与交付物

### GSD 投影与真相分权

- 只读解析项目的 `.planning/`，发现并展示 phase、plan、wave、状态、验证产物和必要的文件链接；不向 GSD 原有格式写入 taskfold 私有字段。
- 定义稳定映射：`project_id + phase_id + plan_id`，并规定 story、task、run 与 phase/plan 的归属关系、创建者和同步方向。
- GSD 产物始终以文件为真相；工作项、运行账本、评论和 taskfold 私有元数据以 SQLite 为真相。任何派生索引都可由 `reindex` 重建。
- 提供 `reindex --dry-run` 对账输出和实际重建；外部手工修改 `.planning/` 后，界面显示差异、索引时间和可恢复的错误。

### GSD 看板与规划视图

- 在看板和详情页显示工作项与 phase、plan、wave 的关联，并可按项目、阶段、波次和执行状态筛选。
- 提供项目规划概览，能跳转到对应 Markdown 产物与验证文件；文件不存在、格式不支持或映射不完整时必须显式提示，不能静默伪造状态。
- M4 先支持一个项目的完整投影链路，再扩展跨项目聚合；跨项目列表不得混淆不同项目的 phase/plan 标识。

### 单 repo 开发执行

- 实现 `Taskfold ACP Runner`：创建或恢复 ACP session、传递受控上下文包、启动 turn、接收结构化状态和摘要事件、取消/关闭 run，并记录 ACP session / run handle。
- 每个 repo 同时只允许一个 active run；每个 run 必须在独立 Git worktree 中执行，运行前记录 HEAD、创建基线提交并校验工作区状态。
- 只在 Execute 阶段允许 agent 写代码；命令、网络、目录、Skill 和预算均受 allowlist/阈值约束，违反前置检查时必须拒绝启动。
- 在 SQLite 保存 `runs` 和 `run_events` 的摘要、成本、关联关系和结果，不复制宿主 transcript 全文；在 `<TASKFOLD_HOME>/runs/` 生成 `META.json`、`TIMELINE.md`、`HANDOFF.md` 等可复盘档案。
- harness 提问、权限拒绝、验证失败、超时、无进展和预算超限必须进入 `awaiting_human`；该状态永不自动跨过。用户可以查看原因、终止 run，或在当前 harness profile 已实测支持时通过真实终端接管。
- 服务重启后执行 reconciliation：恢复可识别的 run，或将无法确认的 run 标为异常并给出人工恢复路径。

## 明确不做

- 不支持同一 repo 多 run 并行；多 worktree 并行与显式合并策略留待 M7。
- 不让 agent 在用户主工作区直接写文件，不把 run 成败等同于人工验收。
- 不改写 `.planning/` 的既有格式，不把 GSD 文件迁移成 taskfold 的数据库记录。

若 OpenClaw 执行 API 验证失败，M1 看板插件保持可用，M4 的执行调度暂停并重新评估后端。

## 退出条件

1. 对一个真实 GSD 项目，`taskfold reindex --dry-run` 能报告将要创建、更新和失效的投影；执行 reindex 后 phase、plan、wave 与源文件可对账。
2. 从关联工作项启动一个官方 ACP harness run：系统创建隔离 worktree、持续展示摘要事件、能够进入并停留在 `awaiting_human`、能够终止或按 profile 终端接管，且最终留下完整运行账本和复盘档案。
3. 重启 taskfold 后，不存在无说明的永久 `running` run；每个异常 run 都有可见原因与处理动作。
