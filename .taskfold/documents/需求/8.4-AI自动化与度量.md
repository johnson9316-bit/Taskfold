# AI、自动化与度量（路线图 M9 规格）

> 跨主题请从 [[README]] 进入；发现矛盾时以 [[1-规划评审]] 为准。本文件定义 [[8-路线图与验收]] 总览中的 **M9**；它在 M4 的可靠执行账本和 M7 的流程能力稳定后实施。

## 目标

把已有的本地工作数据和执行档案变成有边界的建议、自动化和复盘能力，同时通过 MCP 让 Codex、Claude Code、Cursor 等外部开发助手使用同一套 taskfold 工具。自动化负责提出或执行已批准的机械动作，不替用户做关键产品和工程判断。

## 进入条件

1. M4 和 M7 的数据关联、审计记录、权限边界和人工接管路径已稳定，关键状态可以追溯到工作项、GSD 投影或 run 事件。
2. 未配置 AI provider 或禁用自动化时，M1、M4、M7 的核心功能保持可用。

## 范围与交付物

### MCP Server

- 提供面向外部开发助手的 MCP server，覆盖项目/工作项查询、GSD 投影查询、run 查询、受控创建和更新等稳定工具。
- 工具契约与本地 HTTP API 共享领域模型；所有写操作、执行操作和敏感信息访问都有明确权限、参数校验、审计和人工确认。
- MCP 不暴露宿主 session transcript、密钥、未授权工作区或任意文件系统访问；失败信息须脱敏并可诊断。

### AI 建议与自动化规则

- 支持需求澄清、验收标准生成、需求拆解、重复检测、规划建议和复盘摘要等 AI 辅助；输出先以草稿/建议呈现，涉及范围、优先级、写文件、启动 run 或修改状态时必须由人确认。
- 定义 provider 选择、凭证保存、数据最小化、提示注入防护、重试、超时和单次/每日成本上限；未配置 provider 时界面保持可用。
- 提供 YAML 三段式自动化规则（触发器、条件、动作）、语法校验、`dry_run`、执行日志和项目级开关。默认只读/只建议；写操作和执行动作必须再次确认。

### 度量、复盘与报告

- 基于工作项状态、GSD 投影和 `runs`/`run_events` 计算交付周期、阻塞时长、范围变更率、run 成功率、人工介入率、返工率、成本和预算消耗等指标。
- 提供可回溯的度量看板、单 run/单 phase 复盘视图、日报和周报；每个数值必须能定位到数据来源和计算时间，不能把推测写成事实。
- 将 `HANDOFF.md`、验证产物、人工决定和运行摘要纳入复盘索引，用于发现常见卡点和后续 Skill/上下文模板改进。

### 长驻会话增强（可选）

- 在已有 `ACP Runner` 契约下，为已验证支持的 ACP harness profile 增加长驻交互或继续引导能力；不直接接入私有 Agent SDK 作为第二条生产控制路径。
- 默认仍使用 M4 的 OpenClaw ACP Runtime + 官方 `@openclaw/acpx` 路径；长驻能力必须提供同样的 worktree 隔离、预算、审计、终止和 `awaiting_human` 保护。

## 明确不做

- 不把 AI 生成内容自动视为需求、计划或验收结论，不允许自动跨过 `awaiting_human`。
- 不以 MCP 或 AI 功能替代本地 UI，不在本里程碑承诺多人服务、云端托管或新的宿主渠道。

## 退出条件

1. 至少一个受支持的 MCP 客户端可在授权范围内查询 taskfold 数据，并对写入/执行类工具触发可见的确认和审计。
2. AI 与自动化在未确认时只产生草稿或 `dry_run` 记录；超时、超预算、越权和提示注入检测均会停止动作并留下原因。
3. 度量看板、复盘、日报/周报的关键数字可回溯到具体工作项、投影或 run 事件；抽样对账与 SQLite 账本一致。
