# 8.9 卡片图谱与可配置看板

## 1. 目标

在现有项目看板之外，提供同一批 Card 的思维导图和流程图视图，并允许看板按不同规则分列和排序。

看板、思维导图、流程图必须使用同一套项目、里程碑、Card 和 Card 关联数据。图谱只是另一种操作和查看方式，不能形成独立的数据真相。

本功能的图谱范围仅限当前项目。项目创建和项目间移动继续在项目总览及既有项目操作中完成，不在图谱 Tab 中实现跨项目图谱或拖拽换项目。

## 2. 业务定义

### 2.1 节点

图谱中可出现以下节点：

- 项目/看板：项目的根节点。
- 列/分组：当前视图生成的分支节点，不作为独立业务实体保存。
- 需求：父 Card。需求不新建数据表，也不引入另一种“需求”对象。
- 卡片：普通 Card 或子 Card。
- 里程碑：按里程碑分列时的分组节点。

“需求就是父 Card”是本功能的固定规则：

```text
项目/看板 -> 分组列 -> 父 Card（需求）-> 子 Card
```

没有父 Card 的 Card 在“按需求”视图中归入“未归类”。

一张 Card 最多只能归属一个父 Card（需求）。将 Card 拖入另一需求列即更换其父需求；拖入“未归类”即解除其父需求。一个 Card 不同时出现在多个需求列中。

### 2.2 关系

- `contains` / `contained_by`：需求与子 Card 的层级归属关系。`contains` 记录在父 Card，`contained_by` 记录在子 Card；一个子 Card 最多一条 `contained_by`。该关系仅表达需求层级，不影响 Card 的状态、claim 或执行资格。
- `parent` / `child`：保留现有前置依赖语义。子 Card 必须在所有前置 Card 完成后才能进入可执行状态，不能被复用为需求层级。
- `blocks` / `blocked_by`：阻塞关系。
- `relates_to`：普通关联，不影响调度。

上述关系都保存到现有 Card link 数据中，不新建需求表或第二套关系存储。层级关系和前置依赖分别进行循环校验；图谱不得绕过已存在的状态、权限、claim 或执行保护。

## 3. 图谱视图

项目页新增“图谱”Tab，与现有看板、文档、设置并列。图谱 Tab 提供两个模式。

### 3.1 思维导图

- 以当前项目、里程碑或某张父 Card 为根展开。
- 按当前分组规则显示分支；父 Card 下展示子 Card。
- 支持展开/收起分支、缩放、拖动画布、自动布局、适配画布、按里程碑/状态/标签筛选。
- 节点展示标题、状态、优先级、执行状态和子项数量。
- 点击 Card 节点打开现有 Card 详情，不新增第二套详情面板。

### 3.2 流程图

- 展示项目层级、分组节点、父子 Card 和 Card 间连线。
- `contains` / `contained_by` 使用层级连线。
- `parent` / `child` 使用有方向的前置依赖连线。
- 阻塞关系使用有方向的依赖连线。
- 普通关联使用虚线，不影响 Card 是否可执行。
- 支持按关系类型筛选，以及聚焦某张 Card 的上下游关系。

“流程图”默认指任务的层级、依赖和阻塞关系图，不等同于 Card 状态机。状态机如需展示，应作为后续独立视图，不能与任务关系图混合。

### 3.3 图内新增和移动

图谱应支持从上下文节点创建业务项，创建结果必须回写现有数据模型：

| 操作位置 | 创建或变更结果 |
| --- | --- |
| 当前项目根 | 创建未归类 Card |
| 里程碑分组 | 创建里程碑，或创建并归属该里程碑的 Card |
| 需求分组/父 Card | 创建子 Card，并建立父子关系 |
| 状态分组 | 创建具有该状态的 Card |
| Card 节点 | 创建子 Card，或创建前置依赖、阻塞或普通关联关系 |

移动 Card 时，行为随当前分组规则确定：

- 按里程碑：更新 `milestoneId`。
- 按需求：建立、替换或解除 `contains` / `contained_by` 层级关系；移入“未归类”即解除父需求。该操作不得修改既有 `parent` / `child` 前置依赖。
- 按状态：更新 Card 状态。

会改变业务关系的拖拽必须有明确的目标提示和失败反馈。视图模式切换本身不得修改任何 Card。不得把画布坐标当作业务关系保存；首版以自动布局为准。

## 4. 可配置看板

### 4.1 分列规则

每个项目看板可切换以下分列规则：

- `milestone`：按里程碑分列，保持现有项目管理主视图。
- `requirement`：按父 Card（需求）分列；无父 Card 的 Card 放入“未归类”。
- `status`：按 Card 状态分列，例如 backlog、ready、running、review、blocked、done。

“按需求”和“按状态”是分列/分组规则，不是排序规则。

### 4.2 列内排序规则

每个看板保存当前列内自动排序配置：

- `priority`：按 urgent、high、normal、low 排序。
- `createdAt`：按创建时间排序。
- `updatedAt`：按最近更新时间排序。

排序方向必须可选。8.9 不实现按需求或按状态分列时的手工排序，也不为不同分列规则保存多套手工位置。既有按里程碑看板的 `position` 和手工重排行为保持兼容；在按需求或按状态分列时，拖拽只允许改变分组归属，不修改排序结果。

### 4.3 列的创建与限制

列是分组规则的投影，创建列时必须映射到真实业务对象：

- 里程碑模式：新增列即新增里程碑。
- 需求模式：新增列即新增一个顶层父 Card（需求）。
- 状态模式：状态列由系统状态集合决定，不允许新增、删除或手工重命名。

状态模式固定展示全部系统状态列，即使当前没有 Card：`triage`、`backlog`、`todo`、`scheduled`、`ready`、`running`、`review`、`blocked`、`done`。

切换分列规则不创建、删除或迁移 Card，只改变展示方式。

## 5. 数据与接口要求

- 项目读取结果必须能提供图谱所需的 Card、里程碑、Card 状态、父子关系、阻塞关系和普通关联。
- 看板视图配置至少保存 `groupBy`、`sortBy` 和 `sortDirection`，并属于项目/看板，而不是浏览器临时状态。
- 新增 Card、移动 Card、建立或解除层级关系、建立前置依赖及其他关系，全部走现有 Gateway/Store 的受控写入路径。
- 若现有接口缺少解除层级关系、更换父需求、按关系移动或批量读取图谱所需字段，应补充明确的受控接口，不允许 UI 直接修改 SQLite。
- 不新增图谱专用的 Card、关系、状态或列存储。

## 6. 性能与交互边界

- 默认最多渲染 200 个 Card 节点；超过时要求用户按里程碑、状态、标签或根节点筛选/折叠。
- 图谱需正确处理没有关系的 Card、多个根节点、缺失关联目标和已归档 Card。
- 已归档 Card 默认隐藏，可由筛选项显示。
- 节点与连线的颜色、状态名称、提示和错误信息必须接入现有多语言体系。
- 桌面与窄屏下均须保证缩放、聚焦、筛选和打开 Card 详情可用。

## 7. 验收标准

1. 同一项目的看板、思维导图和流程图显示同一批 Card，任一视图中的受控修改会在其他视图刷新后正确反映。
2. 父 Card 被展示为需求节点；`contains` / `contained_by`、前置依赖、阻塞关系和普通关联具有正确的连线样式和方向。
3. 能从项目、里程碑、需求、状态和 Card 节点创建对应 Card/里程碑，并自动写入正确的归属或关系。
4. 一张 Card 最多只有一个父需求；按需求拖拽只修改层级关系，不修改前置依赖或执行资格。
5. 按里程碑、需求、状态切换分列不会修改 Card；按规则拖拽时只修改该规则对应的业务字段。
6. 优先级、创建时间、更新时间排序正确；按需求或按状态分列时，拖拽不会产生错误的 `position` 变更。
7. 尝试创建循环层级、循环前置依赖、无效关系或不允许的状态变更时，操作被拒绝并在 UI 中说明原因。
8. 状态模式固定显示全部系统状态列，且不允许创建、删除或重命名状态列。
9. 图谱只显示当前项目的数据；不提供跨项目图谱或图内项目创建、换项目拖拽。
10. 图谱在节点数超出默认上限时不失控渲染，并提供可用的筛选、折叠或聚焦入口。
11. 现有 Card 执行、状态、里程碑、权限、claim 和审计行为不因新增图谱视图而回归。

## 8. 实现约束与交付说明

本需求按以下边界实现，后续迭代不得在未重新评审的情况下突破：

- 层级固定为两层：`父需求 Card -> 子执行 Card`。不支持需求嵌套需求，也不支持子 Card 再挂子 Card。
- 父需求 Card 使用既有 Card 数据模型，并以 `kind=requirement` 标记；普通执行 Card 使用 `kind=task`。不新增需求专用表。
- 父需求 Card 只承担需求归类和图谱分支职责，不能进入执行准备或启动编码执行。只有普通子执行 Card 可以执行。
- 父子归属使用 `contains` / `contained_by` 成对关系保存到既有 Card link 中；每个子执行 Card 最多一个父需求。该关系与既有 `parent` / `child` 前置依赖完全分离。
- 每个项目持久化一份看板视图配置：`groupBy`、`sortBy`、`sortDirection`。默认保持既有的“按里程碑 + 手工排序 + 升序”行为。
- 图谱和看板只读取、修改当前项目的现有业务数据；不会新增第二套任务、关系或画布坐标存储。

本次交付包含 Gateway、Store、SQLite 迁移、项目看板和图谱界面以及自动化测试。图谱中的拖拽和新建操作必须通过 Gateway 写入，不能由 UI 直接修改本地数据库。
