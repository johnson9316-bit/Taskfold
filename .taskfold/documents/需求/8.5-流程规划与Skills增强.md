# 流程、规划与 Skills 增强（路线图 M7 规格）

> 跨主题请从 [[README]] 进入；发现矛盾时以 [[1-规划评审]] 为准。本文件定义 [[8-路线图与验收]] 总览中的 **M7**；它建立在 M4 的 GSD 投影和运行账本之上。

## 目标

在 M1 的工作管理和 M4 的 GSD/运行账本稳定后，让个人开发者能用同一套界面维护规划、当前重点和执行节奏；同时把 OpenClaw Skills 作为可审计的增强能力，而不是新的真相源或黑盒调度器。

## 进入条件

1. M4 的投影、run 账本、`awaiting_human` 和单 repo、单 worktree 执行闭环已通过 [[8.4-GSD内化与开发执行集成]] 的退出门。
2. 工作项、GSD 产物和 run 记录已有稳定可追溯关联，不以临时字段或手工约定作为跨视图关联依据。

## 范围与交付物

### 流程和规划管理

- 完善 story、task、缺陷和项目的状态机、WIP、依赖、阻塞原因、准入/准出检查；所有流程 gate 默认关闭，可按项目启用。
- 增加路线图、当前重点、表格和跨项目筛选视图，支持从看板跳转到工作项、GSD phase/plan、run 和相关文件。
- 支持把 GSD 规划变化、验证失败和 `awaiting_human` 转化为可处理的工作项；不改变 `.planning/` 的权威性。

### 检索与信息密度

- 为工作项、评论、运行摘要和允许索引的规划文本提供统一筛选与全文检索；SQLite FTS5 必须封装在 `SearchPort` 后。
- 搜索结果必须标出来源、项目、实体类型和更新时间；文件投影索引滞后或失败时不可把旧结果伪装成实时数据。

### Skill 增强

- 增加 `taskflow` 的可选映射：仅记录外部 task ID、依赖和摘要事件，不以它替代 taskfold 的队列、`awaiting_human`、GSD 映射或审计账本。
- 增加 `diagram-maker` 动作，用于生成流程、架构、数据或时序图；输出路径由人选择和确认，图只作为计划附件而不是状态真相。
- 每个 Skill 使用显式 profile、allowlist、版本/可用性检查和审计记录；不可用时保留核心流程，不阻塞项目管理。

### 受控并行执行

- 在 M4 单 run 模型保持可用的前提下，评估多个独立 worktree 的并行 run、队列容量、显式合并顺序和冲突处理。
- 并行执行必须以项目级开关启用，创建 worktree、合并、冲突、清理和验收均可见且可审计；不能依赖 wave “理论上不冲突”作为唯一保障。

## 明确不做

- 不引入 n8n 式流程画布，不让 `taskflow` 替代 taskfold 的调度决策。
- 不自动合并代码或跨过人工验收，不支持多人协作、远程同步和开放网络访问。

## 退出条件

1. 用户能从路线图、当前重点、表格或检索结果定位到同一工作项的看板卡、GSD 产物和 run 记录，且状态来源清楚。
2. `taskflow` 和 `diagram-maker` 缺失或禁用时，M1/M4 核心功能不受影响；启用后，每次动作均有配置来源、输出位置和审计记录。
3. 对至少两个互不冲突的计划，可在独立 worktree 中受控并行运行，并在显式人工确认后完成合并或保留冲突处理记录；默认仍保持单 repo 串行。
