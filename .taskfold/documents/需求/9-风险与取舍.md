# 风险与取舍

> 跨主题请从 [[README]] 进入；发现矛盾时以 [[1-规划评审]] 为准。

| 风险 | 影响 | 应对 |
|------|------|------|
| **状态写入竞态** | 用户同时装了官方 gsd-core 或手工改 MD → 与 taskfold 冲突 | 写 GSD 产物一律经 vendored `gsd-tools.cjs`（拿到 `STATE.md.lock` 语义）；加外部变更检测（[[5-技术架构与选型]]） |
| **vendored 副本腐化** | 上游修复不流入，本地改动与上游冲突，日后无法同步 | 保持干净子树 + `vendor/gsd-core/UPSTREAM` 记录 commit SHA；改动集中在薄适配层（[[5-技术架构与选型]]） |
| **自担 GSD 正确性** | 内化后 GSD 逻辑的 bug 变成自己的 bug | 走 B1（vendor 原样）而非 B2（重写），不引入自造的行为偏差 |
| **格式兼容性丢失** | 私自扩展 `.planning/` 格式 → 与官方 GSD 互不相容，失去采纳入口 | 铁律：不往 `.planning/` 写自有字段，taskfold 独有数据进 SQLite（[[7-数据与接口]]、[[7-数据与接口]]） |
| **偏离 Workboard 基线** | M1 自行重构目录、框架或宿主调用，复制价值消失且难以同步上游 | 固定上游 commit；M1 只改名称、manifest、打包和安装资料；所有功能改造推迟到 M2。 |
| **范围膨胀** | 对标 TAPD 做不完，烂尾 | [[2-产品定位与范围]] 不做清单是硬约束；每个 M 只做一层 |
| **Workboard 复制复杂度** | Workboard 横跨插件、契约和 UI；漏掉直接依赖会导致插件加载或交互失败 | 固定上游 commit，完整复制功能层，保留 `UPSTREAM.md` 与本地 patch；在本机 OpenClaw 中做真实安装和功能冒烟。 |
| **Workboard 上游漂移** | 上游快速演进时，直接跟随会引入不兼容行为或安全回归 | 不把它作为运行时黑盒依赖；固定已验证快照，定期挑选同步，并在 taskfold 冒烟项目中验证后才升级 |
| ~~OpenClaw 无法复用 Hermes IIFE~~ | ~~以为抄完官方 kanban 就跨宿主了~~ | ✅ **v0.8 消解**：Hermes 退场，前端只有一种形态（[[6-OpenClaw集成]]） |
| **OpenClaw 插件 API 兼容性** | 宿主升级可能改变 manifest、UI 或 Gateway 行为，导致 taskfold 无法安装或加载 | 固定已验证的 OpenClaw 版本；每次升级后执行 `plugins inspect --runtime`、`plugins doctor` 和看板冒烟测试。 |
| **ACP 执行集成失效或越权** | OpenClaw、`@openclaw/acpx` 或 harness 升级可能改变 event、权限和执行语义 | `ACP Runner` 只依赖公开 SDK；固定兼容版本；Profile allowlist；升级后在测试项目重跑 ACP Spike。 |
| **⑥ 执行调度：agent 跑飞** | 无人值守时 agent 改错文件、乱提交、装依赖搞坏环境 | 只有 Execute 阶段可放手（[[4-执行调度与AI]]）；`awaiting_human` 永不自动跨过；权限白名单；**Git 是最后防线**——run 前记录 HEAD，出事可回退 |
| **⑥ 同 repo 写入互踩** | 同 wave 的 plan 可能改同一批文件 | M2 固定单 active run + 单隔离 worktree；M3 才评估多 worktree 并行和显式合并。 |
| **⑥ 依赖 OpenClaw ACP 生态被上游改动打破** | ACP Runtime、`@openclaw/acpx` 或 harness adapter 配置项变更 → 执行层失效 | `ACP Runner` 只调用公开 API；固定兼容版本；第 0 期 ACP Spike 与 host contract test；保留官方 CLI backend / 裸 CLI adapter 的评估退路。 |
| **⑥ harness 无法实时打断或恢复** | 不同 ACP adapter 的 cancel、resume、terminal takeover 能力不一致 | Profile 保存 capability；取消后必须状态复核；接管入口只对实测 harness 显示；不支持时明确标示。 |
| **⑥ harness 版本漂移** | adapter 或 CLI 升级改变 event、权限或 session 语义 | 不解析私有文本；只消费公开 ACP event/result/status；升级后重跑相应 harness Spike。 |
| **⑥ 巡检变噪音** | 每天一堆卡没人看，最后全忽略 | 只对 `watched` 项目开；无事不建卡；报告合并成一张；同问题不重复提醒（[[4-执行调度与AI]]） |
| **⑥ 会话成本失控** | 无人值守跑一夜烧掉大量 token | `runs` 记 token 与成本；设单 run 与日预算阈值，超限转 `awaiting_human`（[[4-执行调度与AI]]） |
| **文件 / SQLite 派生索引不一致** | `.planning/` 被外部改动后，界面、run 归属或度量失真 | 每个实体只设一个真相源：GSD 产物在文件，taskfold 原生实体与会话账本在 SQLite；`reindex` 可重建派生索引，`doctor` 负责对账 |
| **未来团队需求打破单机假设** | 若未先设计同步、权限与并发写入便支持小团队，会产生数据冲突与安全问题 | M1-M4 坚持单机个人工具；小团队方向必须单独立项并重评存储、身份与同步模型 |
| **流程管理过度约束** | 个人被繁琐 gate 卡住后弃用 | 准入准出检查器**默认全关**，按需开启 |
| **AI 建议不可信** | 用户不敢用 | 所有 AI 写操作默认 `dry_run`；优先级/范围类决策强制人确认 |
| **插件安装门槛** | 用户无法正确安装或启用插件，M1 无法被复用 | 提供本地链接与 Git 安装说明；从干净 clone 重复安装验证。 |
| **AGPL 代码污染** | 抄了 Plane 代码 → 全项目被迫转 AGPL，商业版归零 | ⚠️ 只从 MIT/Apache 项目取用代码；AGPL 项目只读文档（[[5-技术架构与选型]]） |
| **Python 分发**（⚠️ v0.8 影响面扩大） | 用户没装 Python 就用不了。**v0.7 只影响 VS Code，现在影响 OpenClaw 本身**（npm 包要求外部 Python 环境） | ✅ **转 TS 则此风险归零**（[[11-交接与待决]] 的决策 A）；留 Python 则要求 3.10+ 并考虑 PyInstaller 打平台二进制 |
| **转语言的返工风险**（v0.8 新增） | 转 TS 要重写现有 ~400 行 | 量小、且是最机械的 CRUD；**表结构、状态机、[[5-技术架构与选型]] 十项预留、[[4-执行调度与AI]] 调度设计全部原样成立**，返工仅限实现（[[5-技术架构与选型]] 末） |
| **与宿主原生 Workboard 重叠** | M1 是完整复制，用户看不出差异 | 明确 M1 是插件化基线验证；M2 以多项目、项目设置和项目资料形成第一层产品差异，M4 再加入 GSD 投影和执行调度。 |
| **插件 API 随宿主升级破坏** | 装不上 | manifest 声明兼容版本；CI 冒烟 |
| **Plane 已是 AI-native + MCP** | 差异化被抹平 | 差异点押在 local-first + 宿主内嵌 + MD 可读，而非功能数量 |
