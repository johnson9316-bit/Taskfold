# 竞品与替代方案

> 调研日期：2026-07-28；**2026-10-14 增补社区扫描**（DSH 生态与 ClawHub，见文末「2026-10-14 增补」）。资料来自公开 GitHub README 与仓库 API；功能和活跃度会变化，开工前应再次核实。

## 结论

此前文档有“开源项目选型”，但缺少以用户替代路径、产品重叠和差异化为中心的竞品分析。这个缺口已补上。

taskfold 不能把“AI agent 看板”“多 agent 调度”或“worktree 隔离”当作核心卖点。这一赛道已经有成熟或快速迭代的社区产品。

**当前定位**：面向 AI 代理与个人开发者的**文件化看板**——卡片是仓库里的 Markdown（Backlog.md 格式，Git 可 diff、人可直接编辑），OpenClaw 插件、VS Code 扩展、独立 CLI 三个入口读写同一份文件；执行编排（worktree、派发、认领、对账）是 OpenClaw 宿主提供的能力，不是数据模型的一部分。差异化见文末「2026-10-14 增补」第六节。

## 竞争格局

> ⚠️ 下两表产生于 2026-07-28 的旧定位下；竞品作为「通用 agent 调度台 / 通用研发管理」的存在与重叠仍然成立，本项目的差异点是：Markdown 文件化数据（Git 可 diff、人可直接编辑）、三宿主（OpenClaw / VS Code / CLI）、可靠性设计。

| 分组 | 用户可替代的选择 | 对 taskfold 的意义 |
|---|---|---|
| 通用 agent 调度台 | dev-3.0、kanbots、hopeitworks；Vibe Kanban 为体验基准 | 仍是最大威胁。活跃项目已覆盖多 CLI、并行、worktree、实时观察、人工介入等大部分“调度”功能；Vibe Kanban 可用于研究体验与迁移路径。 |
| Agent 原生规划 | Roadmap Skill、Beads | 覆盖 local-first、依赖图、MCP 与任务状态；taskfold 不能只做又一个任务数据库。 |
| 通用研发管理 | Plane、Linear、GitHub Projects、Planka、Kanboard | 解决协作和看板，但不面向「AI 代理 + 仓库内文件」的工作方式。个人开发者不是它们的最优用户。 |

## 对产品范围的影响

1. **目标用户已收敛为个人开发者。** 不把多人协作、容量排期、权限或团队报表作为近期承诺。
2. **M1 不做通用 agent fleet。** 先证明项目看板本身可用（多项目、里程碑、资料库、交付事实）。
3. **M2 调度只做单 repo、单 run。** worktree、并行波次和自动化运行不是卖点先决条件；先证明工作项到 run 到人工交接的闭环可信。
4. **工作树隔离应保留为后续增强。** 竞品已把它视为并行调度的常规能力，C1 串行化只是风险控制起点，不能成为长期体验终点。
5. **不建立第二份项目真相。** `.taskfold/` 是唯一真相源（[[16-文件存储改造]]）。

## 验证计划

| 优先级 | 验证 | 通过标准 |
|---|---|---|
| P0 | 亲自试用 Vibe Kanban（体验基准）、dev-3.0、kanbots：以同一个个人仓库完成“建任务、启动 agent、需要人决策、验收”的路径 | 写出每一步的摩擦与 taskfold 必须明显更好的一个场景；若找不到，缩减或停止调度层。 |
| P1 | 比较 worktree 模式与同 repo 串行模式 | 明确 C2 的触发条件，例如用户同时运行两个无依赖 Plan 的比例和冲突率。 |

## 需要持续监控的风险

- OpenClaw Workboard 若扩展为通用 agent 调度台，插件内嵌不再构成价值；仍需靠**文件化 Markdown 数据与多宿主**保留定位。
- 竞品多数在快速迭代，所有“未提供”的判断只能作为当前快照，不能作为永久前提。

## 2026-10-14 增补：社区扫描（DSH 生态看板潮 + ClawHub 侧）

> 触发：社区（尤其 DSH 生态）近期涌现大量「工作台/看板」类项目，需核实规模与差异化空间。

### 五、关键发现

1. **存储形态：DSH 邻居全是 JSON，Markdown 无人做。** 已核实的看板实现用 `KANBAN.json` 或单 JSON 文件；没有一个采用 Markdown 卡片、Git 可 diff、Backlog.md 兼容。这与 Taskfold 的核心差异直接相关。
2. **生态在爆发期。** npm `dsh` 抽样（搜索前 250 命中中 217 个 `dsh-*` 包）里，**最近 5 天（10-10～10-14）有 102 个包发过新版**；生态 hub `zhu1090093659/dsh-web` 8720★/571 forks（「万物皆插件，创意工坊分发」），另有插件市场 `dshmarket` v1.66。单包热度普遍低（0～7★）。
3. **旧名 Flowboard 已被公开生态占用**（ClawHub `flowboard`，v5.2.1，2026-06 创建）——改名决定被进一步证实。
4. **重名邻居 `dsh-taskfold` 仍活跃**：npm 0.38.2（2026-10-08 更新）、GitHub 7★（2026-10-09 有 push）。
5. **命名窗口**：`kanbanfile`、`dsh-kanbanfile`、`kanban-file` 在 npm 仍全部空闲（2026-10-14 实测）；但 DSH 侧 `kanban` 词根已高度拥挤（10 个 kanban 包），占位紧迫性上升（见 card-58）。
