# taskfold 规划评审

> 评审日期：2026-07-27。依据 v0.8 规划文本完成桌面审阅，未对 OpenClaw、gsd-core 或代码仓进行实测。本文件的“需修正”结论优先于从原文机械拆分出的旧表述。

## 结论

产品方向有明确差异化：以 GSD 产物为骨架、用看板和调度补齐 gsd-core 的空白。已确认当前只服务个人开发者，并采用 TypeScript + Node。问题集中在“实现前提尚未证实”和“产品模型没有收敛”，不是功能点不足。当前不能把 M1-M2 当作连续开发任务；应先完成验证门和最小模型决策。

## P1：进入对应里程碑前处理

| 问题 | 影响 | 建议 |
|---|---|---|
| story 状态与 Phase 状态重复 | `ready` 后进入 phase，但 story 又有 `doing/verifying/done`；状态样例还缺少 ready 后的转换并引用未声明的 `rejected/deferred`。 | 指定 story 的交付状态是否由关联 phase 投影；补全合法转换、拒绝/暂缓状态、异常流与验收完成的唯一判定。 |
| 数据模型约束不足 | `actor` 的自由字符串无法可靠区分人、agent 与系统；comments 的 MD 与表存储不清；links 无方向和循环约束；run 的 phase/plan 不是外键。 | 先画 ERD 与状态机，再写表。个人版采用 `actor_type + actor_id`；定义评论正文唯一落点和关联完整性。 |
| 长会话恢复语义未定义 | Gateway 重启、CLI 退出、网络失败时，run 可能永久显示 running。 | 设计持久队列、幂等启动键、启动时 reconciliation、超时/重试/终止语义与 orphan run 的人工恢复流程。 |
| M1/M2 范围过大 | M1 若同时改造宿主依赖、重写架构和新增 GSD 功能，会失去复制 Workboard 的价值；此前 M2 同时含 gsd-core 内化、索引、跨项目和调度。 | M1 只交付可安装的 Workboard 复制插件；M2 只做多项目、项目设置和项目资料；GSD 只读投影与单 repo、单隔离 worktree run 的 OpenClaw 执行适配移至 M4。 |
| 实时能力被未验证假设绑住 | WebSocket 是否能穿过 frame 尚未验证。 | M1 验收允许轮询；WebSocket 通过 M1.0 后才列为必达，失败时登记反代或 SSE 方案。 |
| AI 辅助边界不完整 | 独立模式的管理型 AI provider、凭证、成本、隐私、提示注入和失败处理未定义。 | M4 前先写 Provider 选择、数据最小化、写操作审批、重试与成本上限；未完成前只交付不调用模型的功能。 |
| 配置与格式演进缺失 | YAML、卡片文件格式、`.planning/` 都会演进，但没有 schema 版本、迁移、回滚和兼容策略。 | 为配置、卡片文件和投影格式分别定义版本字段、迁移器、备份与 `doctor` 检查。<br>⚠️ 兼容 Backlog.md 后又多一层：**它的格式演进也会影响我们**（[[16-文件存储改造]] 6.2/6.4）。 |

## 已确认决策与阶段门

1. **已确认**：采用 TypeScript + Node；Taskfold 是 OpenClaw 插件，插件 ID 为 `taskfold`、显示名称为 `Taskfold`。现有 Python 资产只保留设计参考。
   > ⚠️ **决策变更（2026-09-24）**：「Taskfold 是 OpenClaw 插件」已被 [[18-多宿主架构]] 推翻——Taskfold 改为多宿主工具，OpenClaw 降为适配层之一。TypeScript + Node、插件 ID `taskfold`、显示名称 `Taskfold` 不受影响，仍然成立。原表述保留作历史记录。
2. B：默认采用 OpenClaw 公共 ACP Runtime + 官方 `@openclaw/acpx`，由 Taskfold 直接调用 `openclaw/plugin-sdk/acp-runtime`，而不是经 LLM Bridge 或第三方执行插件。完成 `doctor`、会话创建/恢复、流式事件、取消/关闭、隔离 worktree、项目 MCP 并存和真终端 resume 实测后才允许进入 M4 执行调度；失败才评估官方 CLI backend 或裸 CLI adapter，不直接上 Agent SDK。
3. C：M4 的第 1、2 期固定“同 repo 单 active mutable run + 单隔离 worktree”。完成 `writeScope` 与并发槽后才评估同 repo 多 worktree 并行与合并策略，不以 wave 假设换取数据损坏风险。
4. `.planning/phases/**/runs/` 在验证上游归档行为前不得写入；先落 `<TASKFOLD_HOME>/runs/`，验证通过后再迁移。
5. **2026-07-28 已确认**：M1 完整复制 OpenClaw 官方 Workboard 功能层作为 `taskfold` 插件，而不是自写 React 看板或独立服务。复制范围是 Workboard 插件、契约包、Workboard UI 页面/状态/样式及其直接依赖；保留其既有宿主依赖、Lit + Vite 和插件规范。
6. **2026-09-18 已确认（范围）**：**本版本只缝合两样——OpenClaw 看板的执行编排 + Backlog.md 的 Markdown 任务存储。GSD 缝合整体推迟**，不在本版本范围内。
   - `.planning/` 的语义投影（phase / plan / wave 映射、可重建索引、GSD 产物读写）**本版本不做，不设计，不预留接口**。
   - 相关规划文档**全部保留**，作为将来缝合 GSD 时的资产，但一律视为"暂缓"，不得据以推导本版本的实现约束。
   - ⚠️ **不影响已交付功能**：`project-document-discovery.ts` 对 `.planning/` 目录的 Markdown 扫描属 M3 Documents 阅读器，只是一个路径白名单，与 GSD 语义无关，**不在推迟范围内，代码不动**。
7. **2026-09-18 已确认（存储）**：**去 SQLite，全部状态改本地文件**，卡片为项目仓库 `.taskfold/` 下的 Markdown 并与 Backlog.md 格式兼容；项目必须绑定本地仓库。完整决策与代价见 [[16-文件存储改造]]。这是对上游 Workboard 的一处**主动偏离**，需在 [[15-上游2026.9.4差异评估]] 登记。

## 缺失但应补充的管理信息

- 目标指标：M1 采用率或试用项目数、M2 单次 run 成功率和人工介入率的基线，不只记录技术指标。
- 责任与节奏：每个里程碑要有负责人、预计工期、复盘日期和“未达标则降级/停止”的条件。
- 用户研究：至少找 3 个现有 GSD 使用者验证“跨项目看板 + 调度”是否比终端工作流更有价值。
- 发布与支持：npm 包命名、兼容的 OpenClaw/Node/CLI 版本、升级回滚、错误日志脱敏、最小隐私声明。
- 质量策略：核心状态机、reindex、队列恢复、权限拦截和 GSD 格式兼容需有自动化测试；插件端需保留真实宿主的烟测。
