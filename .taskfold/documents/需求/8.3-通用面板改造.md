# 通用面板改造（路线图 M3 规格）

> 跨主题请从 [[README]] 进入；发现矛盾时以 [[1-规划评审]] 为准。本文件定义 [[8-路线图与验收]] 总览中的 **M3**。

## 目标

在 M2 项目看板之上，补齐 Card 的真实交付记录，并把项目资料从“路径目录”改造成安全、按需读取的 Markdown 阅读器。M3 记录人已经知道的事实，不从 Card 执行状态或 GSD 文件中猜测事实。

## 范围

### Card 交付记录

- 每张 Card 可选记录 `delivery`：目标、实际交付摘要、待办/阻塞、开发状态、验证状态、发布状态和更新时间。
- 三条交付状态独立于既有 Card `status`：
  - 开发：`not_started`、`in_progress`、`code_complete`、`not_applicable`、`unknown`。
  - 验证：`not_started`、`partial`、`passed`、`failed`、`human_required`、`not_required`、`unknown`。
  - 发布：`not_started`、`pending`、`released`、`not_required`、`unknown`。
- Card 另有手工维护的 `sourceReferences`；它与现有 Proof、Artifact 分开保存和展示。
- 更新交付记录、来源资料、Proof 或 Artifact 时不得改写 Card 状态、领取、执行记录、项目、里程碑、排序或生命周期时间。
- 历史资料不足时必须明确标为 `unknown`；`status=done` 只能表示 Taskfold 执行状态完成，不能推断已验证或已发布。

### Documents 定义

Documents 仅管理 Taskfold 明确定义、需要在面板中阅读原文的项目资料。它不扫描目录，不接管 README 约定，也不将仓库任意文件自动纳入资料库。

新项目固定目录如下：

| 分区 | 资料项 |
|---|---|
| 项目 | 项目概览、需求、路线图、当前状态、复盘 |
| 代码库 | 架构、目录结构、编码规范、测试、外部集成、风险/技术债 |
| 环境与发布 | 开发环境、测试/部署环境 |
| 知识沉淀 | Notes、Research、Todos、Seeds |

- `Project Configuration`、`Technology Stack`、`Onboarding` 不属于固定资料目录。
- 不读取 `config.json`，不维护 `STACK.md`，不自动收录或推断任何 `README.md`。
- 新项目固定资料项和新增本地资料使用具体 Markdown 路径；它们可先作为待绑定项存在，只有绑定实际文件后才可预览。
- 已有的 `markdown`、`json`、`link`、`secret_ref` 资料保持兼容；旧的 `config`、`stack`、`onboarding` 记录不自动删除，并作为可手动删除的历史资料保留。

### Documents 阅读器

- 新增 `taskfold.projects.documents.read({ id })`。它只根据已保存的 Document ID 读取，客户端不能提交任意路径。
- `path` 必须指向存在的普通 Markdown 文件；目录、环境文件、密钥引用、缺失文件、非 Markdown、超过 1 MiB 或无效 UTF-8 的文件均拒绝预览。
- 每次打开和手动刷新才读取；正文只存在于当前 RPC 响应和浏览器内存，不写入 SQLite、不缓存、不索引、不监听变更。
- 读取路径必须通过当前 Gateway 调用者的工作区权限校验；不要求位于项目默认工作区，但解析符号链接后仍必须在允许范围内。
- Documents 页面使用“列表 + 阅读器”：点击资料项阅读经过安全渲染的 Markdown；编辑、隐藏、排序、删除保持独立操作；窄屏保持列表与阅读器可切换。

## 兼容与边界

- SQLite schema 升级到 v5，新增 Card 交付记录和来源资料表；Document 正文不入库。
- M3 不做 GSD 扫描、导入、索引、同步、phase/plan 映射或写回。这些属于 [[8.4-GSD内化与开发执行集成]]。
- M3 不扩展 AI、MCP、执行引擎或项目协作能力。
- 本地路径、链接和密钥引用只保存或展示；Taskfold 不读取凭据值，也不因资料记录授予额外工作区权限。

## ProCloud 回填约定

- `notes`、`todos`、`seeds` 绑定到明确的 Markdown 文件；需要保留的其他真实 Notes 或 Todos 作为显式自定义资料加入。
- 不把 `.planning/config.json`、`STACK.md`、README 或目录本身作为 M3 资料库条目。
- Phase 18、19、20 的交付记录必须写明“代码完成”和真实的验证、发布待办；没有证据的历史结论写为未知。

## 验收

1. v4 数据库升级到 v5 后旧 Card、项目和资料记录可无损读取。
2. Card 交付状态与来源资料可独立编辑、排序和删除，且不会改变执行状态轴或结构归属。
3. Documents 只能按保存 ID 按需读取允许工作区内的具体 Markdown 文件；权限外路径、符号链接逃逸、目录、环境文件、非 Markdown、缺失和超大文件均显示明确错误。
4. 新旧资料兼容，固定目录不再包含配置、技术栈或 onboarding；中英文界面均提供完整文案。
5. ProCloud 的文档、Card 交付事实和来源资料反映真实记录，不将 GSD 的“完成”标签误写成生产验证或发布完成。
