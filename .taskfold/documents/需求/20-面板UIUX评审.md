## 二、环境差异

- **深色测试方式**：宿主 Dark 叠加系统浅色。宿主 Dark + 系统浅色时，`taskfold-app` 仍是 `color-scheme: light`，warn/info/success 取浅色值。**深色数据中 warn/info/success 不代表真深色**，根因见 UX-002。系统本身为深色时的真深色未测。
- **Chrome 自动翻译开着**：文案以 `en.ts` 为准；截图文字可能与实际值错位（UX-039）。
- **窗口尺寸**：Chrome 窗口最大化，`resize_window` 无效，`innerWidth` 一直是 1920。
- **1280 为模拟**：用 `taskfold-app` 内联 `max-width:1002px` 模拟，不触发 `prefers-color-scheme` 或宿主侧栏的媒体查询，宿主侧栏未测。
- **820 / 560 未测**。
- **宿主状态已复原**：`themeMode` 复原为 system；Documents 的「Include archived」测后复原为关；看板 boardView 复原为 groupBy milestone / sortBy createdAt / asc。

## 六、大改项（方案待定，不替用户选）

以下 12 条涉及布局结构、交互方式或视觉方案，每条给出可选方向与代价，决策后再派工。

**UX-010 拖拽键盘替代（高）**
- a) 所有排序与换需求都显示排序 / 移动按钮，并加「移到…」菜单。代价：卡片更挤、按钮增多，需与 UX-044 一起设计。
- b) 卡片聚焦后用键盘快捷键（如 Alt+方向键）移动。代价：需新增快捷键说明，发现性差。
- c) 只把「换需求」下拉补到卡片详情。代价：最小改动，只解决换需求，排序仍只能拖拽。

**UX-011 图谱键盘路径（高）**
- a) 图谱旁增加可聚焦节点列表，列表选中同步画布与 inspector。代价：要维护列表与画布两套选中状态。
- b) 画布内方向键漫游焦点节点。代价：G6 键盘事件需自实现，焦点管理复杂。
- c) 只让 inspector 下拉选卡，画布保持鼠标操作。代价：键盘用户仍无法在图上导航，只补选择路径。

**UX-042 控件边框对比度（中）**
- a) 用 color-mix 从 --text 与 --bg-elevated 派生控件边框 token，统一改一处。代价：VS Code 侧 vscode-theme 映射要重算，需实测达 3:1。
- b) 保留扁平边框，靠填充、焦点环与标签识别。代价：达不到 3:1，设计系统问题 2 不解决。
- c) 新增专用 `--tf-control-border`，亮色、暗色各写一个 hex，约 3:1。代价：两套手调值，维护成本高，宿主主题变化需同步。

**UX-043 图谱颜色随主题（中）**
- a) 节点与边色从 CSS token 取，随主题重绘。代价：需定义映射表（映射到 info / warn / success 与 panel 派生），深浅两套都要测。
- b) 亮、暗两套固定调色板。代价：两套常量维护，宿主新增主题要补。
- c) 节点用形状与描边区分，颜色仅作辅助。代价：改变视觉语言，需设计判断；只解决颜色依赖，不解决对比度本身。

**UX-044 看板每卡两条下拉（中）**
- a) 卡片改为紧凑 chip，点击弹出菜单。代价：多一次点击，菜单需支持键盘。
- b) hover 或 focus 时才显示操作。代价：触屏与键盘下可见性差。
- c) 卡片只显示标题与 chip，编辑全部放到详情。代价：快速改状态变慢。

**UX-045 看板列头字形按钮（中）**
- a) 编辑、完成、归档收进 ⋮ 溢出菜单。代价：多一次点击，需要菜单组件。
- b) 保留 ✎ 编辑与 ⋮ 菜单，完成与归档进菜单。代价：仍有两个按钮，语义清楚，改动比 a 小。
- c) 列头常驻完成按钮，编辑与归档 hover 显示。代价：依赖 hover，键盘不友好。
- 另见 P-8。

**UX-046 看板无高度上限（中）**
- a) 看板限高到视口，列内纵向滚动。代价：滚动层级增加，需在 1280 下测试。
- b) 列分页或左右导航条。代价：交互方式变化，需视觉方案。
- c) 默认折叠空列或过长列。代价：隐藏信息，需提供展开提示。

**UX-047 卡片详情执行区位置与长度（中）**
- a) 分区折叠（手风琴）。代价：需管理折叠状态，关键区可能被忽略。
- b) 页签切换（描述 / 执行 / 元数据）。代价：信息不能同屏对照。
- c) 右侧抽屉分栏。代价：窄屏需降级，布局改动大。

**UX-048 文档编辑工具栏吸顶（中）**
- a) 吸顶工具栏 + 底部固定操作条。代价：占用高度，需测 sticky 在滚动容器中的表现。
- b) 编辑模式全屏覆盖。代价：离开阅读上下文，需明确退出路径。
- c) 保存、取消前移到标题行。代价：长文仍需滚回顶部，只解决一半问题。
