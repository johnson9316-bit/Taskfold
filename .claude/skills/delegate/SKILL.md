# 主代理只规划，执行进子代理的窗口

做完一个功能要花的 token，常常超过一个上下文窗口装得下的量。主代理自己写实现、读整份 diff、跑测试，窗口会在功能做完之前先满。委派不是为了更快，是让任务在物理上能做完：执行的 token 要花在子代理各自的窗口里。

这份 skill 要防的事故是**主代理上下文被执行细节撑爆、功能却还没做完**，不是两个子代理写冲突撞车——并发安全要管，但排在后面。

⚠️ 派发本身有成本：写派工单、等回执、核证据，一轮下来不见得比自己做快。改动就在眼前、一步能做完的自己做——这套流程是给「一个窗口装不下」的活准备的，不是每个任务都该走一遍。

用户开场怎么交代这类任务，见 [kickoff-example.md](kickoff-example.md)。

## 主代理只交方案和派工单

产出只有方案和派工单：不读实现代码、不读整份 diff、不跑会把大段输出倒回上下文的命令（完整测试日志、`cat` 大文件、未过滤的检索结果）。

🔴 自查信号：发现自己正在读实现代码、通读 diff、或者刚把一大段命令输出倒进上下文——这就是在做本该派出去的活。当场停下改派，不要「做完这步再说」。

摸现状、盘老系统、列接口清单这类活，本身就是**第一批**派出去的，不是先自己看一遍再决定派什么。规划要用的是盘点结论，不是盘点过程。

🔴 每张派工单都建立在你此刻对任务的理解上，扇出越大，理解错的代价越大。开跑第一批之前，把你的理解和立论用一两句话说给用户听，等他点头——一句话的确认，换的是整批返工。

## 派工单要交代什么

子代理没见过这次对话。一张派工单钉死四件事：

- **边界**：做到哪一步为止，产出是什么。
- **禁区**：别的子任务正在动的文件和符号；🔴 看不懂来历的内容原样留着回来问——子代理手上的上下文比你还少，最容易把它判成垃圾删掉。
- **产出形式**：要什么（结论 + `file:line`）和**不要什么**（不写文件、不改仓库）都要写。只写前半句，起草类子代理会顺手把稿子落进真文件。
- **歧义**：没交代到的情况回来问，不自己猜。

子代理启动时已经自动带着仓库的 CLAUDE.md，不用贴规范全文；🔴 但要点名这次真会踩、而且踩了不报错的一两条——批量写库默认走 `REPLACE INTO`、写操作漏 `OperationLog::record()` 就静默不留痕、新增路由的鉴权必须挂在 `Route::group` 最外层。

**完成判据**：边界、禁区、产出形式、歧义处理四项，都能在派工单里指出对应的句子。

## 收工单只收结论

子代理默认会把读到的原文整段带回来自证做过——产出形式不钉死，倒原文就是它的默认路径，倒回来等于没省。

🔴 它的总结说的是它**想**做什么，不等于它做了什么。按性价比挑一种客观证据，拿到了才算过：

1. 有对应的窄命令或 `tests/audit`、`tests/api` 用例，跑一次只看退出码和断言数。
2. 没有就 `git diff --stat` 核改动范围有没有越出派工单划的边界。
3. 范围本身就大、又要不带预设结论的复核，另派一个子代理去审——只给它代码和验收条件，不给你的判断。
4. 都够不上，才自己展开读 diff。

🔴 绿不等于对：断言可能只覆盖子代理自己造的那几行，也可能 mock 出了一个现实里不存在的响应形状——测试在认真验证一个虚构。派人加断言，完成判据里要有「先证明它会红」。

⚠️ `git status` 和 `git diff` 都看不见 gitignored 目录（`.claude/`、`.scratch/`）里的改动。派去动这些地方的活，开工前先把原文复制一份进 scratchpad，收工用备份或 mtime 比对——那里出事没有 git 兜底。

方向对但没做到位，用 `SendMessage` 接它的上下文继续调；连续两轮仍不满足验收条件判定跑偏，重开一个新 Agent 并把失败原因写进新 prompt——新开的子代理零记忆，不写就真丢了。重开同样计进这个预算，累计 2~3 次还是跑偏就停止再派，把失败证据整理好直接问用户。

**完成判据**：拿到了上面四种证据之一，不是子代理说「已完成」。

## 并发安全排第二位

先问这一步做完能不能独立验收——凑不出独立验收点，说明还没拆开。再问会不会碰到同一份文件、同一个符号，或**同一份外部状态**——开发库、端口、浏览器会话都算：两个只读子代理各跑一遍写真实库的 `tests/audit`，不共享任何文件也会互相污染出假红，先怀疑是撞了、重跑一次再下判断。碰不到就一起派；🔴 碰得到必须排队，两个子代理同时改同一处是静默覆盖，不报错。拿不准就问「两边能不能各自提交、互不冲突」。

同一条消息里一次性发出多个 Agent 调用是官方保证并发的写法；子代理本身默认后台跑，真正决定「要不要等它」的是 `run_in_background`。⚠️ 改动不重叠但共享同一片工作区时，可以给子代理设 `isolation: 'worktree'`，但它只挡编辑期互相覆盖——真改到同一处，冲突会推迟到合并那一步，还得你自己处理。

派下一个串行任务前 `git status` 看一眼工作树干不干净：基线被上一步的越界改动污染了，下一个子代理会在错的地方接着改。

## 落盘防的是这场会话结束

一个功能常常跨几场会话才做完。落盘防的不只是 compact 把决策压成一句「已确认」，是防这场会话彻底结束。

方案定下来**先落盘再派活**，不要等收尾：活落 `backlog task`，子代理调研回来的盘点/清单/验证结论落 `backlog doc`，架构决策落 `docs/adr/`，方案草稿落 `.scratch/<域>/`。

⚠️ `backlog/` 和 `.scratch/` 都在 `.gitignore` 里。判据是谁要读它：你自己下一场会话读，落这两处够了；要随仓库走（换机器、别人 clone），必须进 `docs/`，交接性质的写 `docs/handover/`。

落盘要连**死路**一起落：被推翻的假设、回滚掉的修法、用户裁决不做的事。下一个接手的（你自己或子代理）默认会先试最顺手的那条路，而那条路往往正是已经试过不通的。

🔴 接续被打断的「进行中」任务前，先看磁盘实物（`git diff`、目标文件在不在、测试能不能过）——backlog 的状态字段、子代理「已跳过 / 已存在」的自述都不算数：可能是真做完了等验收，也可能是半成品。信了状态字段，要么重做已完成的，要么把半成品当定稿。

**完成判据**：把这场对话丢掉，下一场只看盘上的东西也能接着干。

## 高费只留主线

子代理默认走降档模型，机械式照单执行的活留默认档就够；⚠️ 这一步换成你自己做也会切进方案模式细想的（架构选型、有歧义的权衡、需要判断力而非照抄指令），才在这次调用里显式把 `model` 抬回主线当前档位。

## 确认和拍板不外包

用户在场，是跟你一起架构方案的人。范围有歧义、方案有分歧，直接问他，不要派子代理去猜、也不要替他定。commit / push 等不可逆操作同理，自己做。

规划里有不认同、不理解、拿不准的，当场提——照着自己都存疑的方案往下派活，代价比停下来问大得多。

体量明显超出「子代理做得牢、你验得动」的范围时，也是该拍板的时刻：直接说要人工拆，不要硬拆几刀塞进流水线糊弄过去。

## 什么时候改用 Workflow

并行子任务超过 5 个、或要分阶段（先 review 再 verify），手动逐个派 Agent 会乱，改用 Workflow 的 `pipeline()` / `parallel()`——需要用户开口要；他没开口就分两轮派，别一次全甩出去。

⚠️ 跑到一半需求变了：先 `TaskStop` 再带 `resumeFromRunId` 重跑，缓存按 `agent()` 调用顺序做前缀匹配，只有被改动那处**及其之后**会重跑。所以阶段专属的语境要放进阶段专属的常量，别塞进每个 prompt 都插值的那一个——改它等于整轮作废；新增的分支追加到 `parallel()` 数组末尾，前面几路照常命中缓存。
